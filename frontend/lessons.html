01

FIELD NOTE 01 · SECURITY PRINCIPLE

Initial approach

The local access prototype validates form fields with HTML and JavaScript before allowing the workflow to continue.

Limitation

Client-side code runs on a system controlled by the visitor. JavaScript validation can be modified or bypassed completely.

Lesson

Frontend validation improves user experience, but a trusted backend must independently validate all data before making security or business decisions.

02

FIELD NOTE 02 · IDENTITY & ACCESS

Authentication

Authentication establishes who a user is.

Authorization

Authorization determines what an authenticated user is allowed to access or perform.

Lesson

A successful login does not automatically mean the user should have unrestricted access to application resources.

03

FIELD NOTE 03 · ARCHITECTURE DECISIONS

Temptation

A portfolio project can easily become a collection of technologies added solely because they look valuable on a resume.

Design principle

Cloudy Joe introduces new tools only when the platform creates a requirement they are intended to solve.

Lesson

Understanding why a technology is appropriate is more valuable than simply demonstrating that it can be installed or configured.

04

FIELD NOTE 04 · ENGINEERING PROCESS

Approach

The platform begins as a local frontend before adding hosting, authentication, APIs, infrastructure as code, containers, Kubernetes, and AI.

Benefit

Each layer can be understood and tested independently. Failures are easier to isolate because fewer components change at once.

Lesson

Incremental architecture reduces complexity while making technical decisions easier to understand and document.

05

FIELD NOTE 05 · CONTENT DELIVERY

Observation

Uploading a new frontend file to the S3 origin does not guarantee that visitors immediately receive the new version. CloudFront may still have the previous object cached.

Resolution

CloudFront invalidation can remove cached content before its normal expiration, causing a later request to retrieve the updated object from S3.

Lesson

Updating the origin and updating the content delivered by a CDN are separate parts of the deployment process.

06

FIELD NOTE 06 · TROUBLESHOOTING

Challenge

During testing, I discovered that Chrome could display an older version of a protected Resume page without requiring authentic ation, even though other pages correctly redirected to login.

Investigation

I compared normal and Incognito browser sessions and inspected HTTP responses using Chrome DevTools. This revealed that the br owser was loading a previously cached HTML document rather than making a fresh request to CloudFront.

Solution

I configured Cache-Control: no-store on protected HTML responses, invalidated CloudFront's cached objects, and updated my Powe rShell deployment workflow to preserve the configuration automatically.

What I learned

Authentication and authorization aren't the entire security picture. Client-side caching can affect how previously accessed co ntent behaves after logout, making HTTP cache management an important part of designing protected applications.
