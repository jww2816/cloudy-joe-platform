Lessons Learned

Cloudy Joe documents not only what was built, but the mistakes, tradeoffs, and architectural decisions encountered along the way.

Initial approach

The local access prototype validates form fields with HTML and JavaScript before allowing the workflow to continue.

Limitation

Client-side code runs on a system controlled by the visitor. JavaScript validation can be modified or bypassed completely.

Lesson

Frontend validation improves user experience, but a trusted backend must independently validate all data before making security or business decisions.

Authentication

Authentication establishes who a user is.

Authorization

Authorization determines what an authenticated user is allowed to access or perform.

Lesson

A successful login does not automatically mean the user should have unrestricted access to application resources.

Temptation

A portfolio project can easily become a collection of technologies added solely because they look valuable on a resume.

Design principle

Cloudy Joe introduces new tools only when the platform creates a requirement they are intended to solve.

Lesson

Understanding why a technology is appropriate is more valuable than simply demonstrating that it can be installed or configured.

Approach

The platform begins as a local frontend before adding hosting, authentication, APIs, infrastructure as code, containers, Kubernetes, and AI.

Benefit

Each layer can be understood and tested independently. Failures are easier to isolate because fewer components change at once.

Lesson

Incremental architecture reduces complexity while making technical decisions easier to understand and document.
